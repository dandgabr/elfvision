# Security policy

Security maintenance currently targets Gnome AI Quota **0.1** on **GNOME Shell 50**, as declared in `metadata.json`. Reports affecting a development commit are welcome; include its commit identifier so the affected code can be identified. Other released versions and Shell versions are outside the current supported scope.

Report vulnerabilities through [GitHub's private vulnerability reporting channel](https://github.com/dandgabr/gnome-ai-quota/security/advisories/new). The repository's private report form requests a summary, tested versions, technical details, preconditions, reproduction steps or a proof of concept, and impact. Source locations, suggested fixes, and CWE identifiers are optional.

Use synthetic examples and remove API keys, tokens, cookies, credentials, account identifiers, and personal information. Do not include raw configuration files or unreviewed logs. Gnome AI Quota's report actions open GitHub in your browser; they do not gather local diagnostics or submit reports automatically.

Keep vulnerability details in the private report while discussing assessment, remediation, and coordinated disclosure with the maintainer. If the private form cannot be opened, retry that channel; do not publish the vulnerability as a public issue. This project does not promise a fixed response or remediation deadline.

For ordinary bugs, use the [public bug report form](https://github.com/dandgabr/gnome-ai-quota/issues/new?template=bug_report.yml) after reviewing everything you share.

The report structure follows [GitHub's private vulnerability form documentation](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository) and the [GitHub Security Lab report template](https://github.com/github/securitylab/blob/main/docs/report-template.md).
