## Architecture and security review

The implementation follows the approved connector design's pure/GI split. `lib/core/providerRegistry.js` prevents connector core from importing provider runtime services. Legacy default connector IDs and legacy libsecret schema are preserved; added IDs use validated provider-plus-UUID identities and a separate schema with exact provider/connector/kind attributes. Matching retains schema-name participation. Disconnect-all covers both extension-owned namespaces, including credentials orphaned from metadata; exact removal addresses only one connector/kind. Explicit recovery searches metadata with `SearchFlags.ALL`, without loading/unlocking secret values or calling `get_secret`.

Credential renewal and exclusion remain conservative at provider scope, while CAS loads/stores use exact connector identity. This is an intentional documented architectural limitation: deleting one connector may temporarily interrupt sibling runtime work, but cannot erase their credentials. An unresolved failed deletion now prevents a conflicting new scoped deletion; same-target retry or explicitly confirmed global cleanup resolves it. The updated usage guide explicitly states this restriction and the provider-wide account-change block while removal is unfinished.

Exact cache pruning validates both path and opened file type/owner/private permissions and byte bounds, removes only target snapshot/alert keys, and uses an ETag-conditional replacement. Durable exclusion and existing epoch/revision checks prevent late writes from resurrecting deleted state. Demo uses separate metadata/settings and injected fictional controllers with no provider/browser/keyring imports. Restoring Demo retains Demo and cannot implicitly activate live credentials/networking.

Canonical usage and ADR updates accurately describe separate account cards, exact local removal, orphan-aware global removal, preserved reset data, and trusted names in tooltips/notifications. The initial ledger/spec investigation paragraphs are historical evidence, not final implementation certification; their status rows should be reconciled by their owner before delivery.
