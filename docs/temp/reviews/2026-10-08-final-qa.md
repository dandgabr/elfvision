## Strengths

- Durable provider leases exclude same-provider credential writes/deletes across clients without holding the global metadata transaction over keyring I/O. Same-boot orphaned requests remain fenced, and waiting writes revalidate their epoch.
- Conditional replacement compares both generation and original refresh **inside** the provider lease. Token-manager CAS loss discards obsolete pending work and cannot overwrite a new login or resurrect a removed credential.
- Scheduler revision changes cancel the old fetch context immediately and suppress both old successful snapshots and old authentication failures. One replacement fetch follows settled old work.
- Already issued OAuth storage retains its documented settle/announce exception after cancellation or disposal. Attempt-local cleanup now preserves an independently started replacement login.

## Ranked issues and resolution

### P2 — renewal reloads could return access after context cancellation (fixed)

Input: `tokenManager.js` successful renewal and rejected-refresh recovery. Both branches awaited credential reload without immediately rechecking generation/ticket; error settlement also passed through pending-load/save failure accounting without a context check. A synthetic rejected-refresh lookup, followed by `reset()` while held, returned `synthetic-new-access` rather than `disconnected`.

The fix rechecks after successful and failed reloads and failed saves, before returning access or accounting a transient failure. Context loss clears only the pending pair owned by that context, so a fresh request can read the replacement credential. Twelve adversarial reset/stale-ticket tests were RED before the fix; all are GREEN afterward, including fresh-context recovery.

### P2 — a retired OAuth attempt could tear down its replacement (fixed)

Input: `oauthController.js` completion, failure and finalizer callbacks. Gate cancellation could release attempt A, permit B to start, then A's late completion could invoke the shared HTTP closer, cancel B's timers, release B's shared gate and overwrite its failure/busy state.

Each attempt now captures its own HTTP closer; finalization and failure UI changes require ownership of the current login. Browser/timer callbacks check that ownership, and connect catch/finally require the current attempt generation. Ordinary cancellation explicitly releases confirmation ownership. Four old-reply/issued-store cases were RED before the fix and GREEN afterward. A separate held connecting-assertion case verifies that late A failure cannot release B's still-pending reservation; removing its finalizer fence kills that assertion. Existing accepted-save cancellation/disposal assertions still pass.

### P2 test gap — CAS generation guard had no independent assertion (closed)

Input: `secrets.js:37` and existing conditional-rotation tests. Removing **only** the generation comparison survived all three focused rotation cases because the login fixture changed both generation and refresh. A private synthetic same-refresh/new-generation case proved correct source rejects with zero writes while that mutant accepted and wrote once.

Added the same-refresh/new-generation assertion to the owned token-manager test module, avoiding concurrent edits to root-owned disconnect tests. The previously surviving mutation is now killed.
