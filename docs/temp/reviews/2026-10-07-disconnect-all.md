# Durable local disconnect implementation

Date: 2026-10-07. Worktree: `gnome-ai-quota-post-mvp`; integration baseline `800465f`. Implementation owner: reused architecture/security/frontend reviewer thread; no child agents or commits. Parent independently reviewed coordinator, metadata, UI-result and directory-permission boundaries during implementation; each actionable finding received a targeted regression and correction.

## Implemented scope

Accounts has a separate local Disconnect all action. Opening, Cancel, closing and responding after view disposal cannot invoke deletion. Both dialog default and close response are Cancel. Only an explicit live confirmation starts the service. Existing tracking, first-use choice, terms acknowledgements, themes, fonts, usernames and local public client configuration remain saved. No network request or remote revocation occurs.

The service removes the two known credential kinds for each registry provider, verifies absence without loading secret values, removes only `snapshots.json` and `alerts.json` from the live cache directory, and clears account-status IPC. Unknown providers/kinds, demo data and unrelated files remain. Failure does not become success merely because a previous transaction completed: the current UI failure takes priority. Issued-write/delete orphans require reboot; a drain timeout explains acknowledgement and waiting, rather than incorrectly blaming keyring availability.

## Coordination contract

`getDisconnectGate()` is a lazy process singleton. Importing does not read user metadata. `ready()` registers a process participant; `snapshot()` and `isBlocked()` are cached hints. Subscriptions do not invoke immediately. `capture(provider)` and `assertCurrent(ticket)` authoritatively read under the cross-process mutex. Each ticket carries a retained epoch and provider. New explicit user connections capture a new ticket; late results cannot capture a new epoch to rescue an old operation.

`withCredentialWrite(provider,ticket,fn)` persists an issued lease before dispatching an uncancellable Secret Service operation. Promise settlement removes that lease. Both store and transaction deletion requests have leases. Process death, elapsed time or PID reuse does not expire an issued operation within its boot. A prior boot proves the issuing process and local Secret Service cannot still execute. A live timeout remains blocked with the lease intact. Every deletion step and final gate update checks its captured transaction ID and epoch. A second active coordinator, including another call from the same process, is rejected.

Participants cancel network/login work before acknowledging an epoch change. The root extension integration cancels controller and alert services with `flush:false`, clears status and ignores late provider results. API/OAuth controllers retain start tickets, cancel pending login timers/ports/clients, and expose blocked state to account/setup views. Token managers invalidate pending rotation on reset. Ordinary provider disposal retains the rotation cancellation hook until in-flight work settles, preserving normal-lock behavior while allowing disconnect-specific cancellation.

`CacheStore` and `AlertStore` retain one ticket captured on first load; commits never recapture to reuse old cached data. Reads check the ticket before and after the async file read. Commits use asynchronous atomic replacement while holding the metadata mutex, plus per-store invocation ordering. Explicit `{gate:null}` is reserved for the caller's isolated/demo paths and fake fixtures; production defaults are guarded.

## Durable storage and cross-session boundary

Metadata resides in the private application state directory, outside caches being deleted. The schema is bounded to 64 KiB, 64 participants and 64 leases, validates known fields/providers/categories, and carries only process identity, epochs, acknowledgements and fixed outcome categories. Corrupt, missing-required, oversized or unknown fields fail closed. State files are atomically replaced with private permissions; no synchronous file operation was added to Shell write paths. The owned directory/new parent directories use mode 0700; existing unrelated parent permissions remain intact.

A session D-Bus well-known name is the asynchronous metadata mutex, with a module-global queue for stores sharing the same connection and canonical directory. Name ownership ends atomically when its connection dies. An immutable atomically created boot-specific symlink pins the private directory to one bus GUID. Another session bus sharing that directory is rejected within the same boot. This deliberate fail-closed boundary avoids both a new native-helper dependency and unsafe stale filesystem-lock compare/delete races. A different bus requires reboot recovery; no timeout unlocks it. Metadata absence after an ordinary process crash is not used as lease expiry.

Before deletion, the service asks the private/current session bus for the current Shell PID and requires a registered participating process identity. A running older Shell is rejected before any deletion and records a durable `legacyBoot` fence. Replacing it with a participating Shell in the same boot does not remove the fence or permit deletion. A computer restart proves the observed old local process/backend cannot still issue its historical request; retry then resumes the guarded protocol. A missing Shell service permits a guarded transaction. This check identifies a currently unfenced Shell; it does not establish that an unknown historical pre-upgrade Secret Service request has settled after a same-boot Shell replacement. The observed legacy runtime is now reboot-fenced. Requests issued by an unknown historical runtime before the first installation/observation remain unobservable; the implementation does not certify those unknown requests as drained.

## Limits and sources

An actual locked collection was not created in this worker's private real-keyring fixture. The core refusal/partial-failure tests and presence-only search semantics enforce fail-closed behavior; the report does not claim a locked-collection interactive native check. No real OAuth provider login or remote token lifecycle was exercised.

The keyring presence verifier uses search ALL without LOAD_SECRETS or UNLOCK: [libsecret Service.search](https://gnome.pages.gitlab.gnome.org/libsecret/method.Service.search.html). A password-clear boolean reports whether any passwords were removed, so it cannot independently establish complete absence: [password_clear_finish](https://gnome.pages.gitlab.gnome.org/libsecret/func.password_clear_finish.html). Local exact file replacement follows Gio's atomic replacement API: [File.replace_contents](https://docs.gtk.org/gio/method.File.replace_contents.html). The implementation claims process-crash ordering and boot-based recovery, not a separately measured storage-power-loss/fsync guarantee.


The migration-fence regression was first RED (`noteLegacyWriter` absent), then GREEN after adding the durable field and gate method. The same-boot replacement attempts zero credential deletions and cannot capture a ticket; a new boot clears the observation marker and permits explicit guarded retry. The private D-Bus legacy fixture additionally verifies that the PID preflight invokes this durable fence before throwing its fixed computer-restart code.


Close-lifecycle correction: the first regression was RED (two participants remained after the closed writer settled). The last issued store/delete callback now uses one shared settlement helper and retires a closed participant only when no lease remains. The facade detaches its singleton synchronously before awaiting initialization or teardown; old cleanup cannot erase a replacement. The root disables real services with `flush:false` before closing its gate. Tests cover re-enable in the same PID, two subsequent successful disconnects, deletion coordination during close, and no-I/O facade replacement.


Ordinary-disable retirement preserves the accepted token-rotation rule: `retire(pending)` detaches the default singleton immediately while keeping the old delegate, monitor and cancellation hooks operational until pending work settles. It then closes that delegate. `provider.dispose()` returns `tokens.whenIdle().finally(unguard)`; `QuotaController.stop()` returns `Promise.allSettled` for current and previously removed provider disposal work. Disconnect-specific teardown remains `flush:false`. Regressions first failed for absent retirement/stop-return APIs and for prematurely settled removed-provider work, then passed. A replacement gate can disconnect while the old rotation is retiring; the old gate receives cancellation and rejects the late save. No graphical experiments were run for these source corrections.
